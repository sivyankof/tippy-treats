# Правила для Claude Code

Этот файл читается первым. Проект: мобильная игра Tippy Treats (Phaser 4 + TypeScript + Capacitor). Полное описание лежит в `docs/`.

## Порядок работы

1. Перед любой задачей прочитать `docs/10-roadmap.md` и найти текущий этап. Статус этапов ведётся там же, в таблице в начале файла.
2. Прочитать документы, на которые ссылается этап. Не читать всё подряд без нужды.
3. Работать в рамках одного этапа. Не начинать следующий, пока не выполнены критерии готовности текущего.
4. После завершения этапа: прогнать `npm run check`, обновить статус в дорожной карте, сделать коммит.
5. Если реализация расходится с документом, сначала поправить документ, потом код. Документация и код должны совпадать.
6. Если в документации чего-то не хватает или два места противоречат друг другу, спросить владельца проекта, а не выдумывать.

## Команды

`npx cap sync` появится на этапе M7. Остальные работают.

| Команда | Что делает |
|---|---|
| `npm run format` | Prettier по всему коду |
| `npm run dev` | Игра в браузере с горячей перезагрузкой |
| `npm run build` | Продакшен-сборка в `dist/` |
| `npm run test` | Юнит-тесты (Vitest) |
| `npm run coverage` | Юнит-тесты с покрытием `src/core` (порог 85% строк) |
| `npm run lint` | ESLint |
| `npm run typecheck` | `tsc --noEmit` |
| `npm run check` | typecheck + lint + test, запускать перед каждым коммитом |
| `npm run sim` | Бот-симуляция забегов для проверки баланса |
| `npx cap sync` | Копирует сборку в нативные проекты |

## Главные архитектурные правила

1. **Логика отдельно от отрисовки.** Всё в `src/core/` написано на чистом TypeScript и не импортирует Phaser, Capacitor и DOM. Сцены Phaser только показывают состояние и передают ввод.
2. **Все числа баланса лежат в `src/data/`.** В коде логики и сцен не должно быть «магических» чисел скоростей, цен, наград, длительностей анимаций.
3. **Случайность только через `core/rng.ts`** (генератор с зерном). `Math.random()` в `src/core/` запрещён: башня дня должна быть одинаковой у всех игроков.
4. **Нативные возможности только через сервисы** из `src/services/`. У каждого сервиса есть интерфейс и две реализации: нативная и заглушка для браузера. Игра обязана полностью работать в браузере.
5. **Сохранение версионируется.** Любое изменение формы сохранения требует миграции и теста на неё.
6. **Тексты только через i18n.** Никаких строк интерфейса в коде, только ключи. Языки: `en`, `ru`.

## Соглашения по коду

- TypeScript `strict: true`, без `any` (в крайнем случае `unknown` с проверкой).
- Файлы: `kebab-case.ts`. Классы: `PascalCase`. Идентификаторы данных (существа, зоны, события аналитики): `snake_case` строками.
- Код, комментарии и сообщения коммитов на английском. Документация на русском.
- Коммиты в стиле Conventional Commits: `feat(core): add wobble meter`.
- Для каждого модуля в `src/core/` есть тесты рядом: `tower-sim.ts` и `tower-sim.test.ts`.
- Одна сцена Phaser на файл. Сцена не длиннее ~300 строк: крупные куски выносить в объекты `src/game/objects/` и эффекты `src/game/fx/`.

## Phaser 4

- Используется Phaser **4.x** (на ноябрь 2026 актуальна ветка 4.2). API во многом похож на Phaser 3, но рендерер переписан: шейдерные конвейеры, фильтры и часть объектов изменились.
- Не полагаться на память о Phaser 3. Перед использованием нетривиального API (фильтры, маски, частицы, рендер-текстуры, шрифты) проверять документацию Phaser 4: https://docs.phaser.io
- Если какой-то приём из документации проекта не ложится на Phaser 4, выбрать ближайший рабочий вариант и записать решение в `docs/08-architecture.md`, раздел «Журнал технических решений».

## Зависимости

- Не добавлять зависимости без необходимости. Перед добавлением новой runtime-зависимости спросить владельца.
- Для Capacitor-плагинов проверять: поддержка текущей мажорной версии Capacitor, дата последнего релиза, поддержка Swift Package Manager (CocoaPods trunk закрывается на запись в декабре 2026).

## Ассеты

- Графика версии 1.0 рисуется кодом и SVG-файлами в репозитории (см. `docs/06-art-animation-audio.md`). Скачивать чужие картинки нельзя.
- Звуковые эффекты синтезируются через Web Audio. Сторонние звуки и музыка допускаются только с лицензией CC0 или купленной лицензией. Каждый сторонний файл записывать в `assets/LICENSES.md`.
- Не использовать названия, персонажей и узнаваемые элементы чужих игр.

## Чего не делать

- Не реализовывать то, что помечено в документах как «после 1.0».
- Не менять баланс «на глаз» внутри логики: править `src/data/balance.ts` и проверять через `npm run sim`.
- Не добавлять сбор персональных данных, логины и серверную часть: в 1.0 их нет.
- Не вставлять рекламу в местах, не перечисленных в `docs/05-economy-monetization.md`.
- Не коммитить ключи и идентификаторы рекламы/покупок: только через `.env` (в репозитории лежит `.env.example`).
