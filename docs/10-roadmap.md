## M0. Каркас проекта

**Читать:** `CLAUDE.md`, `08-architecture.md` (разделы 1–3, 6).

**Задачи:**
1. Инициализировать проект: Vite + TypeScript (strict) + Phaser 4 + Vitest + ESLint + Prettier.
2. Создать структуру папок из `08-architecture.md`. Пустые модули не создавать, только папки с `.gitkeep`, где нужно.
3. Настроить правило ESLint, запрещающее импорт `phaser` и `@capacitor/*` из `src/core` и `src/data`.
4. `main.ts`: игра запускается, показывает сцену с надписью и счётчиком кадров; масштабирование по ширине 1080 работает при изменении окна.
5. Скрипты `dev`, `build`, `test`, `lint`, `typecheck`, `check`.
6. `.gitignore`, `.env.example`, `assets/LICENSES.md`.
7. Шрифт Nunito положить в `assets/fonts/` и подключить. Если скачать шрифт из среды нельзя, попросить владельца положить файлы.

**Готово, когда:**
- [x] `npm run check` проходит.
- [x] `npm run dev` показывает сцену, которая корректно вписывается в окна 390×844, 430×932 и 360×640.
- [x] Импорт `phaser` в файле внутри `src/core` даёт ошибку линтера.

**Готово, когда:**
- [x] Тесты проходят, покрытие `src/core` ≥ 85%.
- [x] Одинаковое зерно и одинаковые моменты касаний дают одинаковый `RunResult` (тест).
- [x] `npm run sim` печатает таблицу; медианы попадают в диапазоны из `02-gameplay.md`, раздел 12, либо в отчёте этапа предложены правки баланса.

Итог M1 (2026-11-13): на стартовых числах медианы были 20 / 31 / 53 при целях 12–18 / 30–45 / 80–120. Владелец утвердил правки: допуск «идеально» 10 → 20, расширение за комбо со 2-го идеального на 30 (было с 4-го на 20), начальная скорость 520 → 600. После правок медианы 20 / 37 / 87: новичок на 2 слоя выше диапазона (в пределах допуска 25%), остальные в диапазоне.

## M2. Забег на экране

**Читать:** `06-art-animation-audio.md` (разделы 1–3, 5), `07-ui-screens.md` (раздел 4).

**Задачи:**
1. `LayerView`: корж, глазурь, блик, тень рисуются кодом по ширине; простое лицо (глаза, рот).
2. `TowerView`: строит слои по событиям симуляции, применяет качку (смещение и поворот), пул объектов.
3. `FlyingLayerView`, тень-подсказка.
4. `game-scene`: связь ввода и симуляции, камера со сглаживанием.
5. `hud-scene`: высота, очки, шкала качки, пауза.
6. Откусывание: отделяющийся кусок с физикой падения.
7. Простейший фон зоны «Кухня» с параллаксом.
8. Временный экран конца забега: высота и кнопка «Ещё раз».
9. Инструменты отладки: `?debug`, `?seed`, `?bot`, `?start`.

**Готово, когда:**
- [x] В игру можно играть в браузере мышью и касанием; забег перезапускается.
- [x] Качка видна и влияет на прицеливание; чих на 100 работает.
- [x] `?bot=45` играет сам, башня в 100 слоёв держит 60 кадров в секунду на ноутбуке.
- [x] В сцене нет правил игры: только чтение состояния и событий симуляции.

Итог M2 (2026-11-13): проверено в Chromium через автоматизацию. Мышь и касание (эмуляция телефона) роняют слой, касание кнопки паузы не роняет; пауза, «Продолжить» с отсчётом, «Заново» и «Ещё раз» перезапускают забег. Чих проверен событием `wobble_sneeze` (ширина ×0,85, качка 50). `?bot=20&start=96` довёл башню до 122 слоёв при 59–61 кадре в секунду. В dev-сборке игра доступна как `window.tippyGame` для автоматических проверок.

## Как формулировать задания для Claude Code

> Прочитай `CLAUDE.md` и `docs/10-roadmap.md`. Выполни этап **M2**. Сначала перечисли план по задачам этапа и файлы, которые создашь. После реализации пройди по списку «Готово, когда» и для каждого пункта напиши, как ты его проверил. Обнови статус этапа.

Большие этапы (M3, M6) лучше делить на несколько сессий по группам задач.
