# 11a. Сборки для телефона и проверка на устройстве

Инструкция владельцу: как собрать игру для iPhone и Android, поставить её на телефон, открыть отладочное меню и что проверить. Этап M7 (`10-roadmap.md`). Названия кнопок даны так, как они выглядят в интерфейсе; если в App Store Connect или Google Play Console у вас английский интерфейс, английское название стоит в скобках.

## 0. Что где лежит

| Что | Где |
|---|---|
| Проект iPhone (Swift Package Manager, без CocoaPods) | `ios/` |
| Проект Android | `android/` |
| Настройки оболочки (идентификатор `app.tippytreats.game`, цвета заставки, системные панели) | `capacitor.config.json` |
| Сборки в GitHub | вкладка **Actions** репозитория: процессы **iOS** и **Android**, запускаются только вручную |
| Иконки (исходники) | `C:\Users\Artem\Documents\my-projects\tippy-treats-store-assets\` (вне репозитория), все размеры генерирует `scripts/native/make-icons.ps1` |
| Ключ подписи Android | `C:\Users\Artem\Documents\my-projects\tippy-treats-store-assets\android-signing\` (вне репозитория) |
| Готовые файлы (отладочный APK, подписанный AAB) | `C:\Users\Artem\Documents\my-projects\tippy-treats-store-assets\builds\` (вне репозитория) |

Версия, которую видит игрок, одна на всё: `version` в `package.json` (сейчас 0.1.0). Номер сборки растёт с каждой загрузкой в TestFlight или Google Play: в GitHub это номер запуска процесса (можно задать вручную в поле **Build number**), на компьютере параметр `-PbuildNumber=`.

**Внутренняя сборка** (с отладочным меню, раздел 4) и **сборка для магазина** (без него) отличаются одной галочкой **Internal build** при запуске процесса в GitHub или командой на компьютере: `npm run app:sync:internal` против `npm run app:sync`. Для проверок на устройстве ставьте внутреннюю. В магазин для игроков (M9) уходит только сборка без галочки.

Репозиторий публичный, поэтому:
- секреты хранятся только в GitHub Secrets, в журналах сборки они не печатаются;
- подписанные сборки (IPA, AAB) никогда не выкладываются файлами для скачивания: IPA уходит сразу в TestFlight, AAB делается на вашем компьютере;
- отладочный APK выкладывается в GitHub на 1 день: он подписан одноразовым отладочным ключом и для магазина не годится.

## 1. iPhone: подпись и семь секретов в GitHub

Делается один раз. Новых ключей и сертификатов не создаётся: берутся те, что уже есть у команды Apple (проект Arcanum). Ничего не отзывайте и не удаляйте в Certificates, Identifiers & Profiles: сертификат распространения общий, Arcanum подписывается им же.

**Почему так.** Ключ App Store Connect API команды имеет роль App Manager. Такой ключ может загружать сборки, но не может подписывать через облако Apple (`xcodebuild` отвечает «Cloud signing permission error», включить доступ ключу нельзя). Поэтому сборка подписывается вручную: существующим сертификатом распространения и профилем App Store для Tippy Treats, а ключ только загружает сборку в TestFlight.

### 1.1. Ключ App Store Connect API (уже есть)

Идентификатор ключа (Key ID), идентификатор выдающего (Issuer ID) и путь к файлу `.p8` записаны в журнале Arcanum: `arcanum/docs/changelog.md`, поиск «ASC API key». Идентификатор команды Apple (Team ID) — там же, в `arcanum/eas.json` (`appleTeamId`). В репозиторий Tippy Treats эти значения не пишутся: они идут только секретами.

### 1.2. Сертификат распространения из EAS (уже есть)

Сертификат создал EAS для Arcanum, его закрытая часть хранится в Expo. Выгрузите его к себе (только скачивание, на серверах ничего не меняется). Git Bash:

```

npx eas-cli@latest credentials -p ios
```

Ответы на вопросы: профиль сборки **production** → пункт **credentials.json: Upload/Download credentials between EAS servers and your local json** → **Download credentials from EAS to credentials.json**. Появятся файл `credentials.json` (в нём путь к `.p12` и его пароль) и папка `credentials/`. Сразу перенесите их из папки Arcanum в папку ключей, чтобы они не попали в git Arcanum:

```

mv credentials.json credentials /c/Users/Artem/Documents/keys/arcanum-eas/
```

Профиль Arcanum из этой выгрузки Tippy Treats не нужен, нужен только сертификат.

### 1.4. Семь секретов

Готовые команды с точными путями и значениями сессия выдаёт в отчёте, их нужно выполнить в Git Bash. `gh` уже вошёл в аккаунт `sivyankof` с правом на репозиторий. Значение секрета нигде не печатается: файлы и пароль передаются в `gh` напрямую. Вид команд:

| Секрет | Откуда |
|---|---|
| `APP_STORE_CONNECT_KEY_ID` | `gh secret set APP_STORE_CONNECT_KEY_ID --repo sivyankof/tippy-treats --body "<Key ID>"` |
| `APP_STORE_CONNECT_ISSUER_ID` | `gh secret set APP_STORE_CONNECT_ISSUER_ID --repo sivyankof/tippy-treats --body "<Issuer ID>"` |
| `APP_STORE_CONNECT_KEY_P8` | `gh secret set APP_STORE_CONNECT_KEY_P8 --repo sivyankof/tippy-treats < <путь к .p8>` |
| `APPLE_TEAM_ID` | `gh secret set APPLE_TEAM_ID --repo sivyankof/tippy-treats --body "<Team ID>"` |
| `APPLE_DIST_CERT_P12` | `.p12` из `credentials.json` в base64 (команда в отчёте) |
| `APPLE_DIST_CERT_PASSWORD` | пароль из `credentials.json` (команда в отчёте) |
| `APPLE_PROFILE` | `base64 -w0 <путь к .mobileprovision> \| gh secret set APPLE_PROFILE --repo sivyankof/tippy-treats` |

Без `gh` то же делается на сайте: репозиторий → **Settings** → **Secrets and variables** → **Actions** → **New repository secret**, имя в **Name**, значение в **Secret**, **Add secret** (для `.p12` и профиля значение — их base64, его даёт `base64 -w0 <файл>` в Git Bash).

Проверка: `gh secret list --repo sivyankof/tippy-treats` показывает семь имён (значения GitHub не показывает никому). После этого напишите в сессию «секреты внесены»: первую сборку в TestFlight запустит сессия разработки.

## 2. iPhone: сборка в TestFlight и установка

1. GitHub → **Actions** → слева **iOS** → справа **Run workflow**.
2. **target**: `testflight`; **Internal build**: галочка (для проверок); **Build number**: пусто. Нажмите зелёную **Run workflow**.
3. Сборка идёт 10–20 минут. Зелёная галочка значит, что Apple приняла файл. Красный крестик: откройте запуск, шаг с ошибкой покажет причину (частые: нет секрета; неверный пароль `.p12`; профиль не того приложения; номер сборки уже был — запустите с номером больше).
4. App Store Connect → **Приложения** (Apps) → Tippy Treats → вкладка **TestFlight**. Сборка сначала в статусе **Обработка** (Processing), через 5–30 минут готова. Вопрос о шифровании не появится: в проекте указано, что приложение использует только стандартное шифрование.
5. Первый раз: слева **Внутреннее тестирование** (Internal Testing) → **+** → имя группы `Owner` → **Создать** (Create) → в группе **Тестировщики** (Testers) **+** → отметьте себя → **Добавить** (Add). Затем в группе **Сборки** (Builds) **+** → выберите сборку. Дальше новые сборки можно добавлять в эту группу так же или включить **Автоматическое распространение** (Automatic Distribution).
6. На iPhone: поставьте из App Store приложение **TestFlight**, откройте письмо-приглашение (или сразу TestFlight под тем же Apple ID) → **Установить** (Install).

## 3. Android

### 3.1. Отладочный APK из GitHub (для прямой установки)

1. GitHub → **Actions** → **Android** → **Run workflow** → **Internal build**: галочка → **Run workflow**.
2. Через 3–5 минут откройте запуск → внизу раздел **Artifacts** → `tippy-treats-debug-N`. Скачается zip с `app-debug.apk`. Файл хранится 1 день.

4. Отладочная сборка и сборка из Google Play подписаны разными ключами: перед установкой другой удалите прежнюю (прогресс при этом пропадёт).

### 3.2. Памятка другу с Android-телефоном

Перешлите ему файл `tippy-treats-<версия>-<сборка>-debug.apk` из папки `tippy-treats-store-assets\builds\` (Telegram, WhatsApp, почта, Google Диск) и текст ниже.

> **Как поставить.** Открой присланный файл `.apk` на телефоне. Android спросит разрешение на установку из этого приложения (Telegram, Файлы, Chrome — откуда открываешь): нажми **Настройки** → включи **Разрешить из этого источника** → вернись назад → **Установить**. > **Отладочное меню.** На главном экране нажми шестерёнку (настройки), пролистай окно вниз до строки «Версия 0.1.0» (или «Version 0.1.0») и быстро коснись её **5 раз подряд**. Откроется меню на английском.
>
> **Что сделать и прислать:**
> 1. В меню нажми **Perf: no team**. Игра 2–3 минуты играет сама, телефон не трогай. В конце появится таблица и кнопка **copy**: нажми её и пришли скопированный текст. Потом **back to game**.
> 2. Снова открой меню и нажми **Perf: master team**, тоже пришли текст.
> 3. Кнопка или жест «назад» Android: (а) на экране «Магазин» или «Коллекция» — должна вернуть на главный; (б) открой настройки и нажми «назад» — окно должно закрыться; (в) во время игры «назад» ставит паузу, второе «назад» снимает её (3-2-1); (г) на главном экране «назад» сворачивает игру. Напиши по каждому: да или нет.
> 4. Сверни игру посреди забега и вернись: игра на паузе, звук есть?
> 5. Не перекрывает ли что-нибудь вырез камеры вверху и полоску жестов внизу (счёт, кнопки, монеты)? Если да, пришли снимок экрана.
> 6. Модель телефона и версия Android.

### 3.3. Подписанный AAB для внутреннего тестирования Google Play

Подписанный пакет делается только на вашем компьютере: в публичном репозитории его нельзя выкладывать файлом.

**Инструменты** (уже стоят, сессия 8, 2026-11-20). Android Studio не нужна: в `C:\Users\Artem\android-tools\` лежат переносные копии без установщиков и без правки системных настроек:
- `jdk-21.0.13+9` — JDK 21 Eclipse Temurin (Adoptium), архив `OpenJDK21U-jdk_x64_windows_hotspot_21.0.13_9.zip`, SHA-256 `a4dbaa05…832004f9` совпал с api.adoptium.net;
- `sdk` — инструменты командной строки Android SDK 23.0 (`commandlinetools-win-16111833_latest.zip` с dl.google.com, SHA-1 `57d04f2d…8a07e830` совпал с `repository2-3.xml` Google), в них поставлены `platforms/android-36`, `build-tools/35.0.0`, `platform-tools`.

Удалить их — просто удалить папку. Переменные среды не нужны: скрипт сборки находит папку сам (другое место — переменная `TIPPY_ANDROID_TOOLS` или `JAVA_HOME` и `ANDROID_HOME`).

**Ключ подписи** (один раз; его создаёт сессия разработки, когда вы назовёте пароль):
```
TIPPY_KEY_PASSWORD='ваш пароль' bash scripts/native/make-upload-key.sh
```
Скрипт создаёт `android-signing\tippy-upload.p12` (ключ загрузки, псевдоним `upload`, на 30 лет) и локальный файл `android\keystore.properties`, которого нет в git. Пароль храните сами (менеджер паролей). **Ключ и пароль нельзя терять**: с Google Play App Signing потерянный ключ загрузки можно заменить только через поддержку Google, это неделя-две без обновлений. Сделайте копию папки `android-signing` на другой диск.

Пароль — только латиница, цифры и знаки ASCII: Java (Gradle, `jarsigner`) не принимает пароль хранилища PKCS12 с другими буквами, а OpenSSL в Git Bash на Windows читает кириллицу в кодировке 1251. Скрипт такой пароль отклоняет.

**Как сейчас (2026-11-20).** Ключ создан 2026-11-19 с паролем на кириллице, и Gradle его не открывал. Ключ не менялся, его перепаковали:
- `tippy-upload.p12` — исходный файл, не тронут; открывается только `openssl` и прежним паролем (он же записан в `keystore.properties` строкой `originalStorePassword`);
- `tippy-upload-v2.p12` — тот же ключ и тот же сертификат (SHA-256 `FA:B8:02:34:…:8C:9E:F7:A1`, как у `tippy-upload-certificate.pem`) под новым паролем из латиницы и цифр (`storePassword` в `keystore.properties`). Им подписываются сборки.

Перенесите новый пароль из `android\keystore.properties` в менеджер паролей и сделайте копию папки `android-signing` заново: в ней теперь два файла ключа.

**Сборка AAB** (Git Bash в папке проекта; номер сборки — первый параметр):
```
bash scripts/native/build-aab.sh 4            # внутренняя сборка (отладочное меню)
bash scripts/native/build-aab.sh 4 --store    # сборка для игроков (M9)
```
Скрипт собирает веб-часть, переносит её в `android/`, собирает подписанный пакет, кладёт его в `tippy-treats-store-assets\builds\tippy-treats-<версия>-<номер>-<internal|store>.aab` и проверяет подпись (`jarsigner -verify`: «jar verified», подписант `CN=Tippy Treats`, отпечаток SHA-256 — тот же, что у `tippy-upload-certificate.pem`). Каждый следующий AAB для Google Play — с номером больше всех загруженных раньше: Play не примет номер, который уже был.

**Загрузка во внутреннее тестирование:**
1. https://play.google.com/console → Tippy Treats → слева **Тестирование** (Testing) → **Внутреннее тестирование** (Internal testing).
2. Вкладка **Тестировщики** (Testers) → **Создать список адресов** (Create email list) → название `Owner`, ваш адрес Gmail → **Сохранить изменения** (Save changes).
3. Вкладка **Выпуски** (Releases) → **Создать выпуск** (Create new release).
   - Первый раз Google предложит подписание приложений Google Play (**Play App Signing**): оставьте вариант по умолчанию, ключ приложения создаёт и хранит Google, ваш `tippy-upload.p12` остаётся ключом загрузки.
   - **Пакеты приложений** (App bundles) → **Загрузить** (Upload) → `app-release.aab`.
   - **Название выпуска** заполнится само (`1 (0.1.0)`). В **Примечания к выпуску** можно написать «Проверка на устройстве».
   - **Далее** (Next) → **Сохранить и опубликовать** (Save and publish).
4. Вкладка **Тестировщики** → **Скопировать ссылку** (Copy link) в разделе «Как тестировщики присоединяются». Откройте ссылку на телефоне под тем же Gmail → **Стать тестировщиком** → **Скачать в Google Play**.
5. Перед первой публикацией Play Console может попросить заполнить разделы **Политика и программы → Контент приложения** (App content). Для внутреннего тестирования достаточно того, что он требует обязательным; полные анкеты (рейтинг, аудитория 13+, безопасность данных, реклама) — этап M9.

### 3.4. Закрытое тестирование Google Play

**Зачем.** Личный аккаунт разработчика, созданный после 13 ноября 2023 года, не может выпустить приложение для всех, пока не проведёт закрытый тест: **не меньше 12 тестировщиков, которые подписаны на тест без перерыва не меньше 14 дней подряд**. До этого кнопки выпуска в рабочую версию (Production) и предрегистрации закрыты. Тестировщик, который вышел из теста раньше 14 дней, не засчитывается; вышел и вернулся — дни считаются заново. Внутреннее тестирование (раздел 3.3) в эти 14 дней не входит. Проверено по справке Google Play 2026-11-20: https://support.google.com/googleplay/android-developer/answer/14151465.

Там же, 2026-11-20: новые приложения и обновления должны быть нацелены на Android 16 (API 36) с 31 августа 2026 года (https://support.google.com/googleplay/android-developer/answer/11926878). У игры `targetSdkVersion = 36` (`android/variables.gradle`), требование выполнено.

Берите с запасом: 15–20 человек, чтобы выход двух-трёх не сорвал счёт. Тестировщику нужен Google-аккаунт и Android-телефон; весь срок он должен оставаться в тесте с установленной игрой.

**Порядок.** Кто делает: **В** — только владелец (вход в аккаунт, согласия, личные данные, оплата, отправка); **С** — может подготовить сессия разработки (файлы, тексты, ответы для анкет), владелец только вставляет.

## 4. Отладочное меню и замер

Только во внутренней сборке (галочка **Internal build**). В сборке для магазина этого кода нет.

1. Главный экран → шестерёнка (**Настройки**) → внизу окна строка с версией (`Версия 0.1.0`). Быстро коснитесь её **5 раз** (в пределах 2 секунд).
2. Откроется меню на английском (это инструмент, не интерфейс игры):
   - **Perf: no team** — замер без бригады; **Perf: master team** — замер с бригадой мастер-уровня (по нему проверяется бюджет кадра). Замер идёт сам 2–3 минуты, телефон не трогать.
   - **Run from** — старт с выбранной зоны или точки (0/20/40/60/80/100), **Place** — кухня или витрина, **Weather** — погода, **Frame counter** — счётчик кадров, **Debug panel** — панель отладки; затем **Start**. Такие забеги в сохранение не пишутся.
   - **Sound board** — звуковая доска (кнопка **back** возвращает в игру).
   - Раздел **Sound** — строка состояния звука, обновляется раз в секунду (трек, плейлист или трек, удержания, состояние звука, пик музыки `level`, перезапуски сторожа `restarts`). Кнопка **Copy sound report** копирует эту строку и последние 30 строк журнала звука.
   - **Normal start** — обычный запуск, **Close** — закрыть меню.
3. Когда замер кончится, на экране итог: строка вердикта (зелёная `budget: ok` или красная `budget: over in N segments`) и таблица по отрезкам. Кнопка **copy** копирует полный текст, его можно вставить в сообщение для сессии разработки. **back to game** возвращает в игру.

Сделайте оба замера (**no team** и **master team**) и пришлите оба текста.

## 5. Что проверить на устройстве

Отметьте в сообщении по каждому пункту: ок / не ок и что видно. Пункты — приёмка M7 (`10-roadmap.md`).

- [ ] От касания иконки до главного экрана не больше 3 секунд, без белой вспышки (заставка тёмно-шоколадная, затем сразу игра).
- [ ] 60 кадров на башне в 100 слоёв: оба замера из отладочного меню (раздел 4), итог `budget: ok`. Плюс обычный забег с **Run from 100** и **Frame counter**.
- [ ] Сворачивание посреди забега и возврат: забег на паузе, окно паузы на месте, звук и музыка вернулись. Сворачивание на главном экране и возврат: музыка идёт.
