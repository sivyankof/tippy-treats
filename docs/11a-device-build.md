# 11a. Сборки для телефона и проверка на устройстве

Инструкция владельцу: как собрать игру для iPhone и Android, поставить её на телефон, открыть отладочное меню и что проверить. Этап M7 (`10-roadmap.md`). Названия кнопок даны так, как они выглядят в интерфейсе; если в App Store Connect или Google Play Console у вас английский интерфейс, английское название стоит в скобках.

## 0. Что где лежит

| Что | Где |
|---|---|
| Проект iPhone (Swift Package Manager, без CocoaPods) | `ios/` |
| Проект Android | `android/` |
| Настройки оболочки (идентификатор `app.tippytreats.game`, цвета заставки, системные панели) | `capacitor.config.json` |
| Сборки в GitHub | вкладка **Actions** репозитория: процессы **iOS** и **Android**, запускаются только вручную |
| Иконки (исходники) | `C:\Users\Artem\Documents\my-projects\tippy-treats-store-assets\` (вне репозитория), все размеры генерирует `scripts/native/make-icons.ps1` |
| Ключ подписи Android | `C:\Users\Artem\Documents\my-projects\tippy-treats-store-assets\android-signing\` (вне репозитория) |

Версия, которую видит игрок, одна на всё: `version` в `package.json` (сейчас 0.1.0). Номер сборки растёт с каждой загрузкой в TestFlight или Google Play: в GitHub это номер запуска процесса (можно задать вручную в поле **Build number**), на компьютере параметр `-PbuildNumber=`.

**Внутренняя сборка** (с отладочным меню, раздел 4) и **сборка для магазина** (без него) отличаются одной галочкой **Internal build** при запуске процесса в GitHub или командой на компьютере: `npm run app:sync:internal` против `npm run app:sync`. Для проверок на устройстве ставьте внутреннюю. В магазин для игроков (M9) уходит только сборка без галочки.

Репозиторий публичный, поэтому:
- секреты хранятся только в GitHub Secrets, в журналах сборки они не печатаются;
- подписанные сборки (IPA, AAB) никогда не выкладываются файлами для скачивания: IPA уходит сразу в TestFlight, AAB делается на вашем компьютере;
- отладочный APK выкладывается в GitHub на 1 день: он подписан одноразовым отладочным ключом и для магазина не годится.

## 1. iPhone: ключ App Store Connect API и три секрета в GitHub

Делается один раз.

1. Откройте https://appstoreconnect.apple.com → **Пользователи и доступ** (Users and Access).
2. Вкладка **Интеграции** (Integrations) → слева **App Store Connect API** → раздел **Ключи команды** (Team Keys).
   - Если ключей ещё не было, сначала нажмите **Запросить доступ** (Request Access) и согласитесь с условиями. Это может только владелец аккаунта (Account Holder).
3. Нажмите **+** (или **Создать ключ API**, Generate API Key).
   - **Имя** (Name): `GitHub Tippy Treats`.
   - **Доступ** (Access): **Администратор** (Admin). Меньшая роль не даст сборке самой создать сертификат распространения и профиль.
   - Нажмите **Создать** (Generate).
4. В строке нового ключа нажмите **Загрузить ключ API** (Download API Key). Файл `AuthKey_XXXXXXXXXX.p8` скачивается **только один раз**: сохраните его в `tippy-treats-store-assets` (не в папку репозитория).
5. Перепишите два значения с этой же страницы:
   - **Идентификатор ключа** (Key ID): 10 знаков в строке ключа;
   - **Идентификатор выдающего** (Issuer ID): длинная строка с дефисами над таблицей ключей, кнопка **Копировать** (Copy).
6. Откройте репозиторий на GitHub → **Settings** → слева **Secrets and variables** → **Actions** → вкладка **Secrets** → **New repository secret**. Создайте три секрета (имя в поле **Name**, значение в **Secret**, затем **Add secret**):

| Name | Secret |
|---|---|
| `APP_STORE_CONNECT_KEY_ID` | Key ID из п. 5 |
| `APP_STORE_CONNECT_ISSUER_ID` | Issuer ID из п. 5 |
| `APP_STORE_CONNECT_KEY_P8` | всё содержимое файла `.p8`: откройте его Блокнотом и скопируйте целиком, вместе со строками `-----BEGIN PRIVATE KEY-----` и `-----END PRIVATE KEY-----` |

Идентификатор команды Apple (Team ID) сборка узнаёт сама через ключ: это «префикс App ID» вашего идентификатора пакета. Если сборка всё же напишет, что команда не найдена, создайте на той же странице GitHub во вкладке **Variables** переменную `APPLE_TEAM_ID` со значением **Team ID** из https://developer.apple.com/account → **Membership details** (Сведения об участии).

После этого напишите в сессию «секреты внесены»: первую сборку в TestFlight запустит Claude Code и проверит, что она дошла.

## 2. iPhone: сборка в TestFlight и установка

1. GitHub → **Actions** → слева **iOS** → справа **Run workflow**.
2. **target**: `testflight`; **Internal build**: галочка (для проверок); **Build number**: пусто. Нажмите зелёную **Run workflow**.
3. Сборка идёт 10–20 минут. Зелёная галочка значит, что Apple приняла файл. Красный крестик: откройте запуск, шаг с ошибкой покажет причину (частые: нет секрета; ключ не с ролью «Администратор»; номер сборки уже был — запустите с номером больше).
4. App Store Connect → **Приложения** (Apps) → Tippy Treats → вкладка **TestFlight**. Сборка сначала в статусе **Обработка** (Processing), через 5–30 минут готова. Вопрос о шифровании не появится: в проекте указано, что приложение использует только стандартное шифрование.
5. Первый раз: слева **Внутреннее тестирование** (Internal Testing) → **+** → имя группы `Owner` → **Создать** (Create) → в группе **Тестировщики** (Testers) **+** → отметьте себя → **Добавить** (Add). Затем в группе **Сборки** (Builds) **+** → выберите сборку. Дальше новые сборки можно добавлять в эту группу так же или включить **Автоматическое распространение** (Automatic Distribution).
6. На iPhone: поставьте из App Store приложение **TestFlight**, откройте письмо-приглашение (или сразу TestFlight под тем же Apple ID) → **Установить** (Install).

## 3. Android

### 3.1. Отладочный APK из GitHub (для прямой установки)

1. GitHub → **Actions** → **Android** → **Run workflow** → **Internal build**: галочка → **Run workflow**.
2. Через 3–5 минут откройте запуск → внизу раздел **Artifacts** → `tippy-treats-debug-N`. Скачается zip с `app-debug.apk`. Файл хранится 1 день.
3. Перенесите `app-debug.apk` на телефон (кабель, Google Диск, Telegram «Избранное»), откройте его на телефоне → разрешите установку из этого источника (**Настройки** → **Разрешить из этого источника**) → **Установить**.
4. Отладочная сборка и сборка из Google Play подписаны разными ключами: перед установкой другой удалите прежнюю (прогресс при этом пропадёт).

### 3.2. Подписанный AAB для внутреннего тестирования Google Play

Подписанный пакет делается только на вашем компьютере: в публичном репозитории его нельзя выкладывать файлом.

**Что поставить один раз** (сейчас на компьютере нет ни JDK, ни Android SDK):
1. **Android Studio** с https://developer.android.com/studio (кнопка **Download Android Studio**). При установке оставьте всё по умолчанию: вместе с ней ставятся JDK 21 (папка `jbr`) и Android SDK.
2. Запустите Android Studio один раз, пройдите мастер **Setup Wizard** → **Standard**. Затем **More Actions** → **SDK Manager** → вкладка **SDK Platforms** → галочка **Android 16 (API 36)** → **Apply**.
3. Переменные среды Windows (Пуск → «Изменение системных переменных среды» → **Переменные среды** → в верхнем списке **Создать**):
   - `JAVA_HOME` = `C:\Program Files\Android\Android Studio\jbr`
   - `ANDROID_HOME` = `C:\Users\Artem\AppData\Local\Android\Sdk`
   Перезапустите терминал.

**Ключ подписи** (один раз; Claude Code делает это сам, когда вы назовёте пароль):
```
TIPPY_KEY_PASSWORD='ваш пароль' bash scripts/native/make-upload-key.sh
```
Скрипт создаёт `android-signing\tippy-upload.p12` (ключ загрузки, псевдоним `upload`, на 30 лет) и локальный файл `android\keystore.properties`, которого нет в git. Пароль храните сами (менеджер паролей). **Ключ и пароль нельзя терять**: с Google Play App Signing потерянный ключ загрузки можно заменить только через поддержку Google, это неделя-две без обновлений. Сделайте копию папки `android-signing` на другой диск.

**Сборка AAB** (Git Bash в папке проекта):
```
npm run app:sync:internal
cd android
./gradlew bundleRelease -PbuildNumber=1
```
Готовый файл: `android\app\build\outputs\bundle\release\app-release.aab`. Каждый следующий AAB для Google Play — с номером больше (`-PbuildNumber=2` и так далее).

**Загрузка во внутреннее тестирование:**
1. https://play.google.com/console → Tippy Treats → слева **Тестирование** (Testing) → **Внутреннее тестирование** (Internal testing).
2. Вкладка **Тестировщики** (Testers) → **Создать список адресов** (Create email list) → название `Owner`, ваш адрес Gmail → **Сохранить изменения** (Save changes).
3. Вкладка **Выпуски** (Releases) → **Создать выпуск** (Create new release).
   - Первый раз Google предложит подписание приложений Google Play (**Play App Signing**): оставьте вариант по умолчанию, ключ приложения создаёт и хранит Google, ваш `tippy-upload.p12` остаётся ключом загрузки.
   - **Пакеты приложений** (App bundles) → **Загрузить** (Upload) → `app-release.aab`.
   - **Название выпуска** заполнится само (`1 (0.1.0)`). В **Примечания к выпуску** можно написать «Проверка на устройстве».
   - **Далее** (Next) → **Сохранить и опубликовать** (Save and publish).
4. Вкладка **Тестировщики** → **Скопировать ссылку** (Copy link) в разделе «Как тестировщики присоединяются». Откройте ссылку на телефоне под тем же Gmail → **Стать тестировщиком** → **Скачать в Google Play**.
5. Перед первой публикацией Play Console может попросить заполнить разделы **Политика и программы → Контент приложения** (App content). Для внутреннего тестирования достаточно того, что он требует обязательным; полные анкеты (рейтинг, аудитория 13+, безопасность данных, реклама) — этап M9.

## 4. Отладочное меню и замер

Только во внутренней сборке (галочка **Internal build**). В сборке для магазина этого кода нет.

1. Главный экран → шестерёнка (**Настройки**) → внизу окна строка с версией (`Версия 0.1.0`). Быстро коснитесь её **5 раз** (в пределах 2 секунд).
2. Откроется меню на английском (это инструмент, не интерфейс игры):
   - **Perf: no team** — замер без бригады; **Perf: master team** — замер с бригадой мастер-уровня (по нему проверяется бюджет кадра). Замер идёт сам 2–3 минуты, телефон не трогать.
   - **Run from** — старт с выбранной зоны или точки (0/20/40/60/80/100), **Place** — кухня или витрина, **Weather** — погода, **Frame counter** — счётчик кадров, **Debug panel** — панель отладки; затем **Start**. Такие забеги в сохранение не пишутся.
   - **Sound board** — звуковая доска (кнопка **back** возвращает в игру).
   - **Normal start** — обычный запуск, **Close** — закрыть меню.
3. Когда замер кончится, на экране итог: строка вердикта (зелёная `budget: ok` или красная `budget: over in N segments`) и таблица по отрезкам. Кнопка **copy** копирует полный текст, его можно вставить в сообщение для Claude Code. **back to game** возвращает в игру.

Сделайте оба замера (**no team** и **master team**) и пришлите оба текста.

## 5. Что проверить на устройстве

Отметьте в сообщении по каждому пункту: ок / не ок и что видно. Пункты — приёмка M7 (`10-roadmap.md`).

- [ ] От касания иконки до главного экрана не больше 3 секунд, без белой вспышки (заставка тёмно-шоколадная, затем сразу игра).
- [ ] 60 кадров на башне в 100 слоёв: оба замера из отладочного меню (раздел 4), итог `budget: ok`. Плюс обычный забег с **Run from 100** и **Frame counter**.
- [ ] Сворачивание посреди забега и возврат: забег на паузе, окно паузы на месте, звук и музыка вернулись. Сворачивание на главном экране и возврат: музыка идёт.
- [ ] Прогресс переживает выгрузку из памяти: заработайте монеты, сверните игру, смахните её из списка приложений, откройте снова — монеты на месте.
- [ ] iPhone: выключатель звука в положении «без звука» — игра молчит; включён — звук есть. Чужая музыка (Apple Music, Spotify) играет и не обрывается, когда открываешь игру.
- [ ] Входящий звонок (попросите позвонить) и будильник посреди забега: после окончания звонка игра на паузе, звук возвращается (самое позднее после первого касания).
- [ ] Музыка в игре стартует сама, без первого касания.
- [ ] Вибрация: обычный бросок — лёгкий толчок, идеальный — средний, большой откус — сильный, промах — двойной «ошибочный», рекорд на экране итогов — три удара; выключатель «Вибрация» в настройках её отключает.
- [ ] Вырез, «остров» и полоска жестов не перекрывают ничего на всех экранах: главный, магазин, коллекция, бригада, карточка существа, башня дня, забег (счёт, пауза, монеты, полоска качки), окно паузы, «Ещё попытка?», итоги, настройки, задания. Фон при этом доходит до краёв экрана.
- [ ] Android: кнопка или жест «назад» закрывает верхнее окно; в забеге ставит паузу (второе «назад» закрывает окно паузы); на экранах меню возвращает на главный; на главном сворачивает игру.
- [ ] Слои 78–81 и смена зон без рывков (**Run from 60** и играть до 82; и обычный забег до 80+).
- [ ] Поворот телефона: игра остаётся вертикальной.
